## Invalid

Styling for the invalid state is driven by `data-invalid`. Base UI sets it for
you when the input sits inside a `Field.Root` that has failed validation, so
nothing here changes when you adopt one.

<ComponentPreview name='input-invalid' />

## API Reference

`Input` accepts every prop Base UI's `Input` does, plus `className` as a string.

It is Base UI's input rather than a bare `<input>` so that nesting it in a
`Field.Root` later wires up validation and labelling with no change here — the
`data-[invalid]` styling above is what that state drives.
